# OPERATIONS — первичная настройка сервера и деплой

Статус: pipeline и скрипты написаны, **на сервер ещё ничего не развёрнуто**. Образ Docker не собирался в среде разработки (нет Docker-демона) — первая проверка произойдёт в GitHub Actions.

## 0. Безопасность доступа
- Пароль root, отправленный в чат, считать скомпрометированным: **сразу смените** (`passwd`), в идеале перейдите на вход по SSH-ключу и отключите вход по паролю (`--harden-ssh`, см. ниже).
- Секреты вносятся только в GitHub Secrets и на сам сервер. В чат и репозиторий — никогда.

## 1A. Автоустановщик (рекомендуется): одна команда на сервере
Установщик сам: проверит, что `ai.vaylonet.ru` указывает на этот сервер; скачает и запустит настройку сервера; создаст ключ деплоя; создаст в GitHub окружение `production` с обязательным одобрением и запишет в него секреты; сотрёт ключи и токен с сервера.

1. В GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained token**: только этот репозиторий, срок 1 день, права: Administration (RW), Secrets (RW), Contents (R), Actions (RW), Metadata (R). Токен **не отправляйте в чат** — он вводится только в терминале сервера.
2. На сервере от root (ветку `REF` замените на `main`, когда проект слит в `main`):
   ```bash
   REPO=foecerip2/test; REF=main
   read -rs -p "GitHub token: " T; echo
   curl -fsSL -H "Authorization: Bearer $T" -H "Accept: application/vnd.github.raw" \
     "https://api.github.com/repos/$REPO/contents/infra/deploy/install.sh?ref=$REF" \
     | GH_TOKEN="$T" bash -s -- --repo $REPO --ref $REF --domain ai.vaylonet.ru
   ```
   Флаги: `--reviewer ЛОГИН` (кто одобряет деплой; по умолчанию владелец репозитория), `--deploy-now` (сразу запустить первый деплой), `--harden-ssh` (отключить вход по паролю, только если у root есть ключ).
3. Сохраните временный пароль входа на сайт, который скрипт покажет **один раз**. Затем отзовите токен и смените пароль root.

**Безопасный отказ.** Если GitHub не позволяет включить «Required reviewers» (для приватного репозитория это требует платного плана или публичного репозитория), установщик остановится и **не запишет** секреты деплоя: автодеплой без вашей кнопки не включится. Сервер при этом уже будет настроен.

Установщик проверен на подставных `gh` и `bootstrap`, на реальном сервере и GitHub не запускался.

## 1B. Ручная настройка (запасной вариант)
### Однократная настройка VPS-1 (ai.vaylonet.ru → 95.85.247.206)
Выполняется владельцем от root в консоли провайдера или по SSH.

1. Создайте ключ для GitHub Actions прямо на сервере:
   ```bash
   ssh-keygen -t ed25519 -N '' -C github-deploy -f /root/gh_deploy
   cat /root/gh_deploy.pub        # публичный ключ — пойдёт в скрипт
   ```
2. Положите на сервер файл `infra/deploy/bootstrap-vps.sh` из репозитория (например, `nano bootstrap-vps.sh` и вставьте содержимое) и запустите:
   ```bash
   bash bootstrap-vps.sh --deploy-pubkey "$(cat /root/gh_deploy.pub)" --domain ai.vaylonet.ru
   ```
   Скрипт ничего не удаляет. Он ставит Docker, создаёт пользователя `deploy` (ключ которого может выполнить только развёртывание/откат/статус), включает ufw (22, 80, 443), fail2ban, автообновления безопасности и **один раз** выводит временный пароль входа на сайт (логин `owner`) — сохраните его.
3. Скопируйте приватный ключ в GitHub Secret и **удалите файл с сервера**:
   ```bash
   cat /root/gh_deploy      # скопировать целиком, включая строки BEGIN/END
   shred -u /root/gh_deploy /root/gh_deploy.pub
   ```
4. Отпечаток ключа хоста скрипт печатает в конце. Для `DEPLOY_KNOWN_HOSTS` выполните на любой машине `ssh-keyscan -t ed25519 95.85.247.206` и сверьте отпечаток с выведенным скриптом.
5. (Позже, когда вход по ключу проверен) — отключить пароль: `bash bootstrap-vps.sh ... --harden-ssh`. Скрипт откажется, если у root нет ключа.

## 2. GitHub
Settings → Environments → **production**:
- Required reviewers: вы (это и есть «кнопка одобрения»).
- Secrets: `DEPLOY_HOST` (`95.85.247.206`), `DEPLOY_SSH_KEY` (приватный ключ из п. 1.3), `DEPLOY_KNOWN_HOSTS` (вывод `ssh-keyscan`).
Settings → Branches: защитить `main` (PR + зелёный CI).

## 3. Как идёт обновление
`push в main` → CI (lint, types, unit, build, e2e) → сборка образа → **ожидание вашего одобрения** → деплой по digest → проверка здоровья на сервере → автооткат при сбое → проверка снаружи.
Сайт временно закрыт basic-auth (до настоящей авторизации в Фазе 2).

## 4. Откат
- Автоматически: при непрошедшей проверке здоровья сервер возвращает прежний образ.
- Вручную: повторно запустить прежний успешный workflow-run, либо `ssh -i <ключ> deploy@95.85.247.206 rollback`.

## 5. Известные ограничения
- Сторонние GitHub Actions указаны по тегам; перед продакшном закрепить по commit SHA (ADR-007).
- VPS-2 (worker), WireGuard, PostgreSQL, Redis, бэкапы добавляются в Фазе 2 и 6.
- Docker-образ не проверялся локально.
