# OPERATIONS — установка на сервер и обновления

## Как это работает (просто)
1. Разработчик (Claude) готовит изменения в ветке и открывает pull request.
2. **Вы разрешаете слияние в чате** — это и есть ваше одобрение. Без вашего слова в `main` ничего не попадает.
3. После слияния GitHub сам гоняет тесты.
4. Сервер каждые ~3 минуты смотрит на ветку `main`. Как только появился новый коммит **с зелёными тестами**, он сам собирает сайт и запускает. Если новая версия не поднялась — сам возвращает прежнюю.

Кнопок на GitHub нажимать не нужно. Токены, ключи и секреты не настраиваются: сервер сам забирает публичный код, GitHub к серверу не подключается.

> Всё, что попало в `main` и прошло тесты, окажется на сайте. Поэтому: write-доступ к репозиторию держите только у себя, а по желанию включите защиту ветки `main` (Settings → Branches → Add rule → «Require a pull request before merging»).

## Установка на сервер (один раз)
Зайдите на сервер под root (консоль провайдера или SSH) и вставьте одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/foecerip2/Test/main/infra/deploy/install.sh | bash -s -- --repo foecerip2/Test --domain ai.vaylonet.ru
```

Пока изменения не слиты в `main`, замените `main` в ссылке на `ccr-daf26eef-2e6wi4` и добавьте `--ref ccr-daf26eef-2e6wi4`.
Но следить сервер всегда будет за `main`: до слияния PR нечего выкатывать.

Скрипт: проверяет, что `ai.vaylonet.ru` указывает на этот сервер и порты 80/443 свободны (если заняты — ничего не меняет и останавливается); ставит Docker, firewall (22/80/443), fail2ban, автообновления безопасности, swap 2 ГБ; ставит службу обновления; **один раз** показывает временный пароль входа на сайт (логин `owner`) — сохраните его.

Флаги: `--harden-ssh` (отключить вход по паролю; только если у root уже есть SSH-ключ и на сервере есть SSH), `--no-first-run` (не проверять обновления сразу), `--new-password` (выпустить новый пароль входа на сайт и показать его).

Установщик можно запускать повторно: он идемпотентен, настройки и пароль сохраняются, обновляет только службу и конфигурацию.

**Файрвол.** Все уже слушающие внешние порты (SSH, консоль провайдера) остаются открытыми, дополнительно открываются 80 и 443. Если на сервере нет SSH (вход через консоль провайдера), fail2ban и отключение пароля пропускаются.

После установки: **смените пароль root** (он был отправлен в чат) — команда `passwd`.

## Управление на сервере
```bash
lh-update --rollback              # откат на предыдущую версию (откатанный коммит заново не выкатывается)
touch /opt/leadhunter/.paused     # приостановить автообновление;  rm /opt/leadhunter/.paused — возобновить
journalctl -u lh-update -n 50     # что делала служба обновления
systemctl list-timers lh-update.timer
docker compose --env-file /opt/leadhunter/.env -f /opt/leadhunter/docker-compose.prod.yml ps
```

## Откат
- Автоматически: если новая версия не прошла проверку здоровья, сервер возвращает прежнюю и больше её не пробует.
- Вручную: `lh-update --rollback`. Или попросите разработчика слить в `main` исправление/возврат (`git revert`).

## Ограничения
- Установщик и служба проверены на подставных `git`/`docker`/GitHub API; на реальном сервере ещё не запускались, как и сборка Docker-образа (в среде разработки нет Docker-демона) — первая настоящая сборка пройдёт в CI.
- Сторонние GitHub Actions указаны по тегам; перед продакшном закрепить по SHA (ADR-007).
- До появления настоящей авторизации (Фаза 2) сайт закрыт временным паролем (basic-auth).
- Сборка идёт на самом сервере. На маленьком сервере (например 1 ядро, 2 ГБ RAM) установщик добавляет swap 3 ГБ, а сборка занимает 5–10 минут; при нехватке памяти сборка может не пройти — тогда версия помечается неудачной и остаётся прежняя.
- Публичный GitHub API без токена ограничен 60 запросами в час с одного IP; служба делает 2 запроса при каждой проверке только когда нужно, поэтому укладывается в лимит.
