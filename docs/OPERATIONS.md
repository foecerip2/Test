# OPERATIONS — установка на сервер и обновления

## Как это работает (просто)
1. Вы (или я) вносите изменения → они попадают в ветку `main` на GitHub.
2. GitHub сам гоняет тесты. Если всё зелёное, он создаёт **черновик релиза**.
3. Вы открываете черновик и нажимаете **«Publish release»** — это и есть кнопка одобрения.
4. Сервер каждые ~3 минуты смотрит на GitHub, видит опубликованный релиз, проверяет, что тесты прошли, собирает сайт и запускает. Если новая версия не поднялась — сам возвращает прежнюю.

Никаких токенов, ключей и секретов в GitHub настраивать не нужно. Сервер сам забирает публичные релизы; GitHub к серверу не подключается.

> Право «Publish release» есть у всех, у кого есть запись (write) в репозиторий. Держите write-доступ только у себя.

## Установка на сервер (один раз)
Зайдите на сервер под root (консоль провайдера или SSH) и вставьте одну команду:

```bash
curl -fsSL https://raw.githubusercontent.com/foecerip2/Test/main/infra/deploy/install.sh | bash -s -- --repo foecerip2/Test --domain ai.vaylonet.ru
```

Пока изменения не слиты в `main`, замените `main` в ссылке на `ccr-daf26eef-2e6wi4`.

Скрипт: проверяет, что `ai.vaylonet.ru` указывает на этот сервер и порты 80/443 свободны (если заняты — ничего не меняет и останавливается); ставит Docker, firewall (22/80/443), fail2ban, автообновления безопасности, swap 2 ГБ; ставит службу обновления; **один раз** показывает временный пароль входа на сайт (логин `owner`) — сохраните его.

Флаги: `--harden-ssh` (отключить вход по паролю; только если у root уже есть SSH-ключ), `--no-first-run` (не проверять релизы сразу).

После установки: **смените пароль root** (он был отправлен в чат) — команда `passwd`.

## Первый запуск сайта
1. Слейте pull request в `main`.
2. Дождитесь зелёных тестов (вкладка Actions) → в разделе **Releases** появится черновик.
3. Откройте его → **Publish release**.
4. Через несколько минут откройте `https://ai.vaylonet.ru` (логин `owner` и пароль из установки).

## Откат
- Автоматически: если новая версия не прошла проверку здоровья, сервер возвращает прежнюю.
- Вручную через GitHub: у нужного старого релиза нажмите «Set as the latest release».
- Вручную на сервере: `lh-update --rollback`.

## Диагностика
```bash
journalctl -u lh-update -n 50        # что делала служба обновления
systemctl list-timers lh-update.timer
docker compose --env-file /opt/leadhunter/.env -f /opt/leadhunter/docker-compose.prod.yml ps
```

## Ограничения
- Установщик и служба проверены на подставных `git`/`docker`/GitHub API; на реальном сервере ещё не запускались, как и сборка Docker-образа (в моей среде нет Docker-демона) — первая настоящая сборка пройдёт в CI.
- Сторонние GitHub Actions указаны по тегам; перед продакшном закрепить по SHA (ADR-007).
- До появления настоящей авторизации (Фаза 2) сайт закрыт временным паролем (basic-auth).
- Сборка идёт на самом сервере (4 ГБ RAM): первая сборка занимает несколько минут.
