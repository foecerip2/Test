# AutoFlow — продукт (план, статус: proposed)

**Суть (слова владельца):** принимает заявки и записывает клиентов автосервиса; подписка помесячно; дальше развиваем.

Всё ниже — предложение, ждёт утверждения владельца. Цены, тарифы и сроки владельцем не заданы.

## Пользователи
- **Автосервис** (владелец/администратор): кабинет — заявки, расписание, услуги, клиенты.
- **Клиент автосервиса**: публичная страница записи автосервиса (ссылка/QR), без регистрации — имя, телефон, услуга, время.

## MVP (минимум, чтобы взять первого платящего пилота)
1. **Публичная страница записи** у каждого автосервиса: выбор услуги и свободного времени, ввод имени и телефона, согласие на обработку данных.
2. **Заявки и расписание**: список заявок, статусы (новая / подтверждена / выполнена / отмена), боксы или мастера, рабочие часы, исключения, защита от двойной записи.
3. **Уведомления**: автосервису — о новой заявке (e-mail и push в Android-приложении); клиенту — подтверждение и напоминание (e-mail; SMS/мессенджеры — позже, платные каналы только с согласия владельца).
4. **Кабинет автосервиса** (веб + Android-приложение Capacitor, как ADR-013).
5. **Подписка**: пробный период, тариф, статус оплаты. Платёжный провайдер выбирает владелец (расходы и договор — решение владельца).
6. **Юридическое**: политика обработки персональных данных (152-ФЗ), оферта, согласие клиента; данные хранятся в РФ.

## Не входит в MVP
Онлайн-оплата услуг клиентом, складской учёт, CRM-воронки, интеграции с 1С и внешними каталогами, AI-ассистент.

## Технически
- Новый контур: `apps/autoflow-web`, `apps/autoflow-api` (или общий API с отдельными таблицами и арендатором `tenant_id`); вход по e-mail коду переиспользуем.
- Мультиарендность: каждый автосервис = арендатор; изоляция данных проверяется тестами.
- Тот же сервер и тот же автодеплой (ADR-014); отдельный поддомен.

## Порядок работ
1. Лендинг AutoFlow (что это, цена пилота, форма «хочу пилот»).
2. Демо-автосервис: публичная страница записи + кабинет.
3. Пилот у 1–3 автосервисов, замеры.
4. Подписка и оплата, Android-приложение.

## Вопросы к владельцу
- Название и домен (поддомен `ai.vaylonet.ru` или отдельный).
- Цена подписки и длительность пробного периода (ориентир).
- Платёжный провайдер.
- Юрлицо/ИП или физлицо (влияет на приём оплаты и документы).

## Заявки на пилот: статус реализации (backend)
Сделано (`apps/api`, миграция `0004`): публичный `POST /api/v1/autoflow/pilot-requests`, кабинет владельца (`GET`/`PATCH`), счётчик `pilot_requests_new` в `GET /api/v1/dashboard`, аудит без персональных данных. Подробности — `docs/API.md` («AutoFlow: заявки на пилот») и `docs/SECURITY.md`.

Открытые пункты:
- **Уведомление владельца о новой заявке по e-mail — отдельным шагом.** Существующая почта (в т.ч. HTTPS-ретранслятор `infra/mail-relay`) умеет только код входа; расширять её произвольным текстом нельзя (безопасность, ADR-015). Нужен отдельный безопасный канал (фиксированный шаблон письма «новая заявка» без ПД в теме, либо push). Пока владелец видит счётчик на дашборде и запись в журнале аудита.
- Передать в окружение API `AUTOFLOW_DOMAIN` (или `AUTOFLOW_ORIGINS`) и включить `TRUST_PROXY_HEADERS` в prod (compose/`lh-config` — отдельным шагом, `infra/` в этой задаче не менялся).
- Страница списка заявок в кабинете владельца (веб).
- Срок хранения и удаление заявок по запросу субъекта ПД.
