# PRD: «Комбайн» — сервис конвейеров из нейросетей

Статус: черновик 1 · Рабочее название: «Комбайн» · Макет: см. `docs/design/mockup.html`

## 1. Суть

Пользователь запускает цепочку нейросетей, где результат одной модели становится входом для другой, и получает готовый материал (текст, картинки, озвучку, видео) без ручного переключения между сервисами. Платит кредитами за каждый запуск.

**Одно предложение:** «Опишите идею — получите готовый ролик, подкаст или набор картинок за один запуск».

## 2. Проблема

- Чтобы сделать ролик из идеи, человек вручную ходит по 4–5 сервисам: пишет сценарий в одном, картинки генерирует в другом, озвучивает в третьем, монтирует в четвёртом.
- Каждый сервис отдельная подписка, свой интерфейс, свои форматы файлов.
- Повторить результат с новой идеей приходится заново, весь путь вручную.

## 3. Целевая аудитория

| Сегмент | Что нужно | Приоритет |
|---|---|---|
| Авторы контента и SMM | Быстрый регулярный контент: ролики, карточки, подкасты | Основной |
| Малый бизнес | Описания товаров, посты, рекламные ролики без студии | Основной |
| Разработчики и энтузиасты | Собрать свою цепочку из разных моделей | Вторичный (после MVP — API) |

## 4. Цели и метрики

| Цель | Метрика | Целевое значение (через 3 мес. после запуска) |
|---|---|---|
| Люди доходят до результата | Доля новых пользователей, завершивших первый запуск за сессию | ≥ 50 % |
| Повторное использование | Пользователи с ≥ 2 запусками за неделю | ≥ 25 % |
| Монетизация | Доля платящих среди активных | ≥ 5 % |
| Устойчивость экономики | Валовая маржа с учётом стоимости API | ≥ 40 % |
| Надёжность | Доля запусков, завершённых без ошибки | ≥ 95 % |

## 5. Принципы продукта

1. **Результат, а не настройка.** Новичок запускает готовый шаблон за три клика; редактор схемы нужен только тем, кто хочет глубже.
2. **Цена видна до запуска.** Пользователь всегда знает, сколько кредитов спишется, и никогда не получает минус.
3. **Конвейер — это данные.** Схема хранится как версионированный граф; запуск воспроизводим.
4. **Модель — заменяемая деталь.** Шаг описывает «что сделать» (текст→картинка), конкретная модель выбирается отдельно и меняется без переделки схемы.
5. **Частичный сбой не ломает запуск целиком.** Шаги повторяются, упавший шаг можно перезапустить, неудавшееся не списывается.

## 6. Пользовательские сценарии

**S1. Запуск шаблона (основной).** Пользователь открывает каталог → выбирает «Ролик из идеи» → вводит идею одной фразой → видит оценку стоимости → нажимает «Запустить» → наблюдает прогресс по шагам → получает видео, скачивает его.

**S2. Правка шаблона.** Пользователь открывает шаблон в редакторе → меняет модель на шаге «Кадры» (дешевле или качественнее) → цена пересчитывается → сохраняет как свой конвейер → запускает.

**S3. Пополнение.** Баланса не хватает → сервис показывает, сколько не хватает, и предлагает пакет кредитов → после оплаты пользователь возвращается к запуску.

**S4. Повтор и история.** Пользователь открывает прошлый запуск → видит вход, результат каждого шага → запускает заново с другой идеей или перезапускает один шаг.

## 7. Функциональные требования

Приоритеты: **P0** — обязательно для MVP, **P1** — сразу после MVP, **P2** — позже.

### 7.1 Аккаунты
- P0: регистрация и вход по email (ссылка/код) и через один OAuth-провайдер.
- P0: профиль, баланс кредитов, история запусков.
- P1: подтверждение email как условие для бесплатных стартовых кредитов (защита от абьюза).

### 7.2 Каталог шаблонов
- P0: 4–6 готовых шаблонов (ролик из идеи, статья в подкаст, карточки для соцсетей, описание товара).
- P0: у каждого шаблона описание, схема-цепочка, оценка стоимости и времени.
- P1: категории и поиск.

### 7.3 Редактор конвейера
- P0: просмотр схемы шаблона как графа; выбор шага; смена модели и параметров шага (формат, количество).
- P0: пересчёт стоимости при любом изменении.
- P1: добавление и удаление шагов, соединение портов с проверкой совместимости типов (текст/картинка/аудио/видео).
- P1: сохранение личных конвейеров с версиями.
- P2: ветвление по условиям, циклы, пользовательский код.

### 7.4 Запуск
- P0: форма входных данных, определяемая схемой конвейера.
- P0: оценка стоимости до запуска; резервирование кредитов в момент старта; списание по факту, возврат за неудавшиеся шаги.
- P0: статусы запуска и шагов (в очереди → идёт → готово / ошибка / отменён) с обновлением в реальном времени.
- P0: параллельные ветки выполняются параллельно, шаг ждёт все свои входы.
- P0: повтор шага при временной ошибке провайдера (до 2 раз с задержкой); перезапуск упавшего шага вручную.
- P0: отмена запуска, возврат кредитов за невыполненные шаги.
- P1: запасная модель при недоступности основной.
- P1: пакетный запуск (один конвейер на список входов).

### 7.5 Результаты
- P0: превью (текст, картинка, плеер аудио/видео), скачивание, копирование ссылки.
- P0: хранение результатов 30 дней, затем удаление; пользователь может удалить раньше.
- P1: публичная ссылка на результат.

### 7.6 Кредиты и оплата
- P0: баланс в кредитах; журнал операций (пополнение, резерв, списание, возврат, бонус).
- P0: пакеты кредитов, оплата через выбранного платёжного провайдера.
- P0: стартовый бонус новым пользователям.
- P1: подписка с ежемесячным начислением.
- P1: автопополнение.

### 7.7 Администрирование
- P0: управление каталогом моделей и их ценой в кредитах без релиза.
- P0: просмотр запусков, ошибок и затрат на API по провайдерам.
- P1: ручное начисление и возврат кредитов, блокировка пользователя.

## 8. Нефункциональные требования

| Область | Требование |
|---|---|
| Производительность | Старт запуска (запись + постановка в очередь) < 1 с; обновление статуса шага доходит до экрана < 2 с |
| Надёжность | Запуск возобновляется после перезапуска воркера; шаги идемпотентны, повторная доставка задачи не удваивает списание |
| Безопасность | Ключи провайдеров только на сервере; доступ к данным по владельцу (RLS); подписанные ссылки на файлы с ограниченным сроком; проверка вебхуков оплаты по подписи |
| Защита от абьюза | Лимиты запусков и параллельных запусков на пользователя; проверка баланса до запуска; ограничение размера входа и выхода |
| Наблюдаемость | Логи с id запуска и шага; метрики длительности и ошибок по провайдерам; алерты на рост ошибок и расходов |
| Доступность интерфейса | Клавиатурная навигация, контраст не ниже 4.5:1, уважение `prefers-reduced-motion`, светлая и тёмная темы |
| Языки | Русский в первой версии; тексты вынесены из кода для добавления английского |
| Адаптивность | Рабочий интерфейс от 375 px; редактор на телефоне — просмотр и запуск, правка схемы на широком экране |

## 9. Монетизация

- **Единица учёта — кредит.** Цена шага в кредитах = себестоимость API × наценка (стартово 1,7 ×), округление вверх. Курс и пакеты настраиваются в админке.
- **Стартовый бонус:** кредитов хватает на 1–2 запуска шаблона.
- **Пакеты** (стартовые, уточнить после теста себестоимости): малый, средний, большой со скидкой за объём.
- **Подписка** (P1): месячное начисление кредитов, неиспользованные сгорают через 1 месяц.
- **Защита маржи:** цена пересчитывается при смене тарифов провайдера; оценка перед запуском использует актуальные цены.

## 10. Технические решения (предварительно)

| Область | Решение | Причина |
|---|---|---|
| Фронтенд | Next.js, TypeScript, Tailwind, React Flow для графа | Быстрый старт, SSR для лендинга, готовый граф-редактор |
| Бэкенд | Next.js route handlers + отдельный воркер на Node | Один стек, воркер масштабируется отдельно |
| Очередь | Redis + BullMQ | Повторы, задержки, параллельные ветки, приоритеты |
| База | PostgreSQL (Supabase) с RLS | Аутентификация, права и реальное время из коробки |
| Файлы | S3-совместимое хранилище, подписанные ссылки | Дёшево, срок жизни настраивается |
| Модели | Адаптеры: OpenRouter (текст), fal.ai (картинки/аудио/видео) | Много моделей через два ключа |
| Деплой | Vercel (веб) + контейнер для воркера | Простота; воркер не живёт в серверлесс-функциях |

**Модель исполнения.** Версия конвейера хранит граф шагов. При старте создаётся запуск и строки шагов; воркер берёт шаги, у которых все входы готовы, вызывает адаптер модели, сохраняет результат как файл или текст и ставит в очередь следующие шаги. Резервирование и списание кредитов выполняются атомарно в базе (см. `docs/schema.sql`).

## 11. Риски

| Риск | Вероятность | Влияние | Что делаем |
|---|---|---|---|
| Себестоимость выше цены (длинные входы, дорогие модели) | Средняя | Высокое | Оценка до запуска, потолок на вход и выход шага, наценка настраивается |
| Провайдер падает или меняет цены | Высокая | Среднее | Повторы, запасная модель (P1), цены в БД |
| Генерация запрещённого контента, блокировка ключей | Средняя | Высокое | Фильтр на входе, условия использования, лимиты, логирование |
| Абьюз бонусов (мультиаккаунты) | Высокая | Среднее | Бонус после подтверждения email, лимит по устройству/IP |
| Оплата недоступна в нужной юрисдикции | Средняя | Высокое | Выбрать платёжного провайдера до начала разработки оплаты |
| Права на результат, персональные данные | Средняя | Высокое | Юридическая проверка условий, отдельная политика хранения |
| Долгие запуски раздражают | Высокая | Среднее | Прогресс по шагам, уведомление по готовности, возможность закрыть вкладку |

## 12. Вне объёма MVP

Публичный API и ключи пользователя, командные рабочие пространства, маркетплейс чужих конвейеров, собственные дообученные модели, мобильное приложение, интеграции с соцсетями для публикации.

## 13. Открытые вопросы

1. Платёжный провайдер и валюта (зависит от аудитории и юрисдикции).
2. Нужен ли вход по номеру телефона или хватит email и OAuth.
3. Первые 3 шаблона для запуска: порядок по ценности и по сложности реализации.
4. Хранить ли пользовательские входные данные дольше 30 дней для истории.
5. Нужна ли модерация вручную на старте.

## 14. План этапов

| Этап | Содержание | Результат |
|---|---|---|
| 0. Основа | Репозиторий, схема БД, аутентификация, дизайн-токены | Пустой каркас с входом |
| 1. Движок | Очередь, адаптеры моделей, выполнение графа, кредиты | Запуск шаблона из консоли и API |
| 2. Интерфейс | Каталог, форма запуска, прогресс, результаты, история | Полный сценарий S1 |
| 3. Оплата | Пакеты, вебхуки, журнал | Сценарий S3, закрытая бета |
| 4. Редактор | Правка шагов и моделей, версии | Сценарии S2, S4 |
| 5. Усиление | Лимиты, алерты, тесты, ревью безопасности | Публичный запуск |
