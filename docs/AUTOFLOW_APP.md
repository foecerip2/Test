# AutoFlow: закрытое приложение

## Разделение

- `/` — публичный лендинг для трафика и заявок на пилот.
- `/login`, `/register` — настоящий вход по коду из письма и регистрация с сохранением профиля.
- `/app` — расписание, `/app/services` — услуги, `/app/resources` — боксы/мастера, `/app/settings` — автосервис, `/app/pilots` — заявки с лендинга.
- Само приложение пока доступно только активному `owner`. Новая регистрация создаёт профиль и экран ожидания, но не доступ к рабочим данным. Обычный `active user` тоже не является администратором AutoFlow.

Используется существующий `OWNER_EMAIL`: владелец входит своим адресом. Пароли и дополнительные ключи не нужны. База для нового владельца пустая: настройте название/город/часы, добавьте услуги и боксы, создайте первую запись. Демонстрационные данные не подставляются в приложение.

## Что работает

Данные хранятся в PostgreSQL: аккаунт, автосервис, услуги, ресурсы, записи и сведения о согласии. Услуга задаёт длительность и справочную стоимость. У записи есть клиент, телефон, дата, время, бокс, комментарий и статус. Сохранение переживает перезагрузку; отмена освобождает время. Приложение проверяет шаг 15 минут, рабочие часы, прошлые даты и пересечения.

Одновременные изменения одного бокса сериализуются `SELECT ... FOR UPDATE`. Проверка занятости выполняется после получения блокировки. При реактивации отменённой записи проверка повторяется. Это проверяется конкурентными тестами на PostgreSQL; локальный SQLite не заменяет эту проверку.

Кабинет использует ежедневные часы работы и московское время. Исключения по дням, перенос записи, изменение/архивирование услуг и ресурсов, публичная клиентская запись и её уведомления — последующие этапы. Онлайн-оплаты и подписок пока нет. Согласие на обработку заявки не считается согласием на рекламу.

## Авторизация и изоляция

Ядро идентификации и таблица e-mail-пользователей общие с LeadHunter. Сессии и OTP-запросы имеют отдельный `application`; cookies AutoFlow — `af_session` (HttpOnly) и `af_csrf`. Токен или challenge одного продукта не принимается другим. Выход AutoFlow не закрывает LeadHunter.

Новая регистрация AutoFlow не создаёт участия в LeadHunter и не попадает в его список ожидающих одобрения. Для участия в LeadHunter нужен отдельный подтверждённый вход в него. Пользователь не может установить роль, статус или владельца контура из формы. У каждого администратора свой рабочий контур; услуги, боксы и записи фильтруются сервером по нему. Заявки на пилот — общая административная очередь.

Мутации приложения проверяют Origin по существующему `AUTOFLOW_DOMAIN`/`AUTOFLOW_ORIGINS` и CSRF. На закрытых маршрутах установлен noindex, а API не кешируется. Скрытие ссылок и robots.txt не заменяют серверную проверку прав.

Коды доставляются существующим почтовым каналом. Внешний PHP-ретранслятор пока формирует прежнее фиксированное письмо LeadHunter; произвольный текст/тема ему не передаются. Отдельное брендирование писем AutoFlow потребует совместимого обновления самого ретранслятора на почтовом хостинге. Доставка настоящего письма проверяется владельцем при входе; автоматические браузерные тесты используют подставную доставку.

## Миграция

`0005`: дополнительные поля членства/контекста сессии, таблицы `af_*`. Существующие пользователи и сессии сохраняют поведение LeadHunter. Миграция аддитивная; штатный запуск API выполняет `alembic upgrade head`. Откат приложения не требует удаления новых таблиц. Ручной downgrade удаляет данные AutoFlow и не должен использоваться как обычный откат production.

## Проверки

API: `cd apps/api && pytest` (после установки `.[dev]`).

Для PostgreSQL задайте `TEST_POSTGRES_URL` на **одноразовую тестовую БД**: тесты очищают её схему. В CI используется отдельный PostgreSQL 16. Локально конкурентные проверки выполнены на PostgreSQL 17.

Веб: `pnpm --filter autoflow-web lint`, `typecheck`, `test`, `build`, `e2e`. Для e2e нужен Python с установленным `apps/api[dev]`; при локальном venv задайте `AF_TEST_PYTHON=/путь/к/apps/api/.venv/bin/python`.

Браузерный набор запускает настоящий FastAPI и временную SQLite. Только доставка почты подставная; код 123456 существует исключительно в тестовом сервере `tests/browser_autoflow.py` под явным флагом `AUTOFLOW_BROWSER_TEST=1`. Этот модуль не входит в production-образ, а production API не имеет тестового кода или обхода входа.

Реальные сценарии: регистрация → ожидание; вход владельца → настройки → услуги/боксы → запись → перезагрузка → конфликт времени → изменение статуса; публичная заявка → административный список → статус и заметка. Есть проверки WCAG A/AA, клавиатуры, reduced-motion и запрета доступа.

CI: `web` и `api` выполняются параллельно. Стабильный job `test`, которого ждёт `lh-update`, проходит только после успеха обоих. Зависимость PostCSS обновлена через override и lockfile; аудит production-зависимостей не находит известных уязвимостей.

## Android

Новый APK открывает `/app`, а не лендинг. Без сессии пользователь попадает на вход, без административных прав — на ожидание. `AUTOFLOW_URL` по-прежнему принимает только HTTPS-домен; `/app` добавляется автоматически. Обновлены адаптивная иконка/экран запуска. Изменение начального URL требует установки нового APK; старый APK по-прежнему может перейти в кабинет через «Войти» на сайте.

Существующий workflow использует временный ключ APK, поэтому установка поверх ранее подписанного APK может потребовать удаления старого приложения. Постоянный ключ публикации пока не настроен; не передавайте его в чат.
