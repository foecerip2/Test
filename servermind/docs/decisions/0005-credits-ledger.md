# ADR 0005 — Кредиты: ledger, резервы, квоты, администратор беты

Статус: **реализовано и проверено автотестами** (Фаза 5, часть «Credits») · Дата: 2026-11-10

## Решение
1. **Единицы.** Кредиты — целые минимальные единицы (`BIGINT`). Никакой привязки к деньгам: оплаты нет, кнопка «Пополнить» отключена («скоро»). Кредиты на закрытой бете начисляет администратор платформы.
2. **Ledger** (`ledger_entries`) — источник истины, **append-only** (триггер БД на UPDATE). Виды проводок: `credit`, `reserve`, `capture`, `release`, `adjustment`. Знак: все суммы положительные, кроме `adjustment`. Уникальность `(organization_id, idempotency_key)`.
3. **Кошелёк** (`wallets`) — кэш суммы проводок с CHECK в БД: `balance >= 0`, `held >= 0`, `held <= balance` (доступный остаток не бывает отрицательным, даже если ошибиться в коде). Сверяется с проводками функцией `ledger.verify()`.
4. **Резервы** (`ledger_reservations`): `open → captured | released` ровно один раз. Списание — по фактическим токенам, **не больше резерва** (перерасход не списывается, помечается в проводке), остаток резерва возвращается проводкой `release`.
5. **Конкурентность.** Все операции организации сериализуются блокировкой строки кошелька (`FOR UPDATE`), порядок «кошелёк → резерв». Идемпотентность проверяется под этой блокировкой; уникальный индекс — страховка.
6. **Чат в режиме Credits.** Ключ платформы берётся из окружения (`PLATFORM_AI_KEY`, в БД/логи/ответы не попадает). Порядок: проверка лимитов расходов → резерв (отдельная транзакция) → вызов провайдера → списание в той же транзакции, что и ответ. При нехватке кредитов провайдер **не вызывается**. При сбое провайдера резерв освобождается, сообщение пользователя не сохраняется (повтор не дублирует). Сбой ключа платформы не приписывается пользователю.
7. **Висящие резервы** (падение процесса между резервом и списанием) освобождает воркер раз в минуту (`release_stale`, порог `STALE_RESERVATION_MINUTES`).
8. **Цены задаёт оператор** (`PRICE_IN_PER_1K`, `PRICE_OUT_PER_1K`, `PRICE_LIST_VERSION`): они не выдуманы и не зашиты. Пока ключ платформы или цены не заданы, режим недоступен (`409 mode_unavailable`). Версия прайс-листа записывается в проводку.
9. **Квоты:** `CREDITS_DAILY_CAP` / `CREDITS_MONTHLY_CAP` (списания организации за 24 ч / 30 суток; проверка с запасом на резерв); лимит запросов в час на пользователя уже есть (Фаза 3).
10. **Администратор платформы** — пользователь из `PLATFORM_ADMIN_EMAILS` (для остальных эндпоинты отвечают 404). `POST /admin/credits/issue` требует `idempotencyKey` и причину, пишет аудит `credits.issued`; повтор с тем же ключом не начисляет и не дублирует аудит. `GET /admin/audit` — общий журнал.

## Настройка на сервере (`/opt/servermind/env/api.env`)
```
PLATFORM_ADMIN_EMAILS=["you@example.com"]
PLATFORM_AI_PROVIDER=openai          # openai | anthropic | deepseek
PLATFORM_AI_MODEL=<имя модели>
PLATFORM_AI_KEY=<ключ платформы>
PRICE_IN_PER_1K=<кредитов за 1000 входных токенов>
PRICE_OUT_PER_1K=<кредитов за 1000 выходных токенов>
PRICE_LIST_VERSION=2026-11
CREDITS_DAILY_CAP=5000               # по желанию
```
После правки: `docker compose -p servermind --project-directory /opt/servermind/compose up -d api`. Файл `api.env` права 600; ключ платформы в чат/логи не выводить.

## Что НЕ сделано / не проверено
- Ни одного вызова реального провайдера платформенным ключом (в песочнице нет ключа и исходящего доступа): проверены только сценарные заглушки.
- Токенизация и cached tokens у провайдеров отдельно не тестировались; фактические токены берутся из ответа провайдера как есть.
- Оценка резерва консервативная, но не точная: при росте входа между итерациями цикла перерасход не списывается (платформа его absorbs).
- Автоматическая оплата, возвраты, счета — не реализованы (нет платёжного провайдера).
- Админка: флаги функций, приглашения, отключение пользователя, kill switch на уровне платформы **не реализованы** (эндпоинты отвечают 404, интерфейс показывает ошибку секции). Реализованы выдача кредитов и общий журнал.
