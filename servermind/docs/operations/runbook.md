# Руководство по эксплуатации ServerMind

Все команды — на VPS с установленным ServerMind (`/opt/servermind`), от root/sudo. Что проверено, а что нет, указано в конце.

## 1. Администратор платформы
Админ-функции (выдача кредитов, подключение AI-моделей, флаги, приглашения, пользователи, kill switch) доступны только пользователям из `PLATFORM_ADMIN_EMAILS` в `/opt/servermind/env/api.env`. Установщик задаёт его сам (`--create-owner` или `--platform-admin EMAIL`). Для уже установленного сервера:
```bash
echo 'PLATFORM_ADMIN_EMAILS=["you@example.com"]' >> /opt/servermind/env/api.env
docker compose -p servermind --project-directory /opt/servermind/compose up -d api
```
Дальше: «Админка» в интерфейсе (нужна 2FA). Кредиты и модели — [ADR 0005](../decisions/0005-credits-ledger.md).

## 2. Бэкап и восстановление (restore drill)
Автообновление делает бэкап БД перед каждой миграцией (`/opt/servermind/backups/db-*.dump`, 5 последних). **Бэкап, который не восстанавливается, не бэкап** — проверяйте:
```bash
sudo bash /opt/servermind/bin/restore-drill.sh            # самый свежий; рабочую базу НЕ трогает
```
Скрипт восстанавливает дамп во временную базу, проверяет версию миграций, ключевые таблицы и триггеры неизменяемости журналов, печатает число строк и удаляет временную базу. Код выхода ≠ 0 — бэкап негоден. Делайте это раз в месяц и после установки.

Восстановление данных при аварии (остановите `api`, чтобы он не писал): `docker compose … stop api web`, затем `docker compose … exec -T postgres pg_restore -U servermind -d servermind --clean --if-exists < /opt/servermind/backups/db-….dump`, `up -d`. **Схема БД не откатывается вместе с образами** (см. deployment.md §5).
Копии бэкапов лежат на том же диске: настройте вынос за пределы сервера (например, `rsync`/`rclone` по cron) — без этого потеря диска = потеря данных.

## 3. После перезагрузки VPS
Контейнеры имеют `restart: unless-stopped`, таймер автообновления включён (`Persistent=true`). Проверка:
```bash
sudo bash /opt/servermind/bin/post-reboot-check.sh
```
Проверяет: docker активен и в автозапуске, таймер активен и включён, все контейнеры `running/healthy` (ждёт до ~2 минут), сайт отвечает локально, состояние релиза на месте. Код ≠ 0 — в выводе указано, что именно не поднялось.

## 4. Кредиты: сверка
```bash
docker compose -p servermind --project-directory /opt/servermind/compose exec -T api python -m app.cli ledger-verify
```
Сверяет кошельки со всеми проводками (баланс, открытые резервы, неотрицательность); код 1 — расхождение (никогда не должно быть; при появлении — сообщите и не меняйте данные руками).

## 5. Реальное исполнение
Выключено по умолчанию. Установка обёртки на целевой сервер и включение выключателей — [target-wrapper.md](target-wrapper.md). Аварийная остановка: «Админка → kill switch» или `EXECUTION_ENABLED=false` и перезапуск `api`.

## 6. Что проверено и что нет
- ✔ `restore-drill.sh`: выполнен в песочнице на реальной схеме (миграция 0008): `pg_dump -Fc` → `pg_restore` во временную БД → проверки → удаление; повреждённый дамп распознан (код 1). `shellcheck` чисто.
- ✔ `post-reboot-check.sh`: 13 тестов на подставных docker/systemctl/curl (все ветки: нездоровый контейнер, неактивный таймер, docker без автозапуска, 5xx, нет релиза). `shellcheck` чисто.
- ✔ `ledger-verify`: тест на реальной БД (OK и обнаруженная подмена кошелька).
- ✘ **На реальном VPS** restore drill и перезагрузка **не выполнялись**: сделайте их после установки и пришлите вывод, если что-то не так.
