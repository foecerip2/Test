# SECURITY и threat model (обновлено после Фазы 2)

Принципы: AI — недоверенный планировщик; никаких произвольных shell-команд; least privilege; честные статусы; никаких секретов в чате, git, логах, prompts, browser storage.

## Границы доверия
1. Browser — недоверенный: CSRF-заголовок + HttpOnly/SameSite=Lax cookie.
2. API — авторизация + `organization_id` из сессии на каждом ресурсе.
3. LLM — недоверенный вывод; логи серверов — потенциальный prompt injection (Фаза 3).
4. Worker — единственный исполнитель изменений, только каталог одобренных операций (Фаза 4).
5. Целевой VPS принадлежит клиенту; отдельный пользователь `servermind` без docker group и безусловного sudo.

## Угрозы и меры (статус по факту; «проверено» = есть автотест, прошедший в сессии)
| Угроза | Мера | Статус |
|---|---|---|
| IDOR / подмена organization_id | tenant берётся только из сессии; чужое = 404; лишнее поле в запросе игнорируется | реализовано, проверено (pytest) |
| MITM по SSH | закреплённый ключ хоста (`known_hosts=[pinned]`), отпечаток подтверждает владелец, при несовпадении команды не выполняются | реализовано, проверено на тестовом SSH-сервере; **на реальном VPS не проверялось** |
| SSRF / metadata / DNS rebinding | запрет private/loopback/link-local/CGNAT/reserved/metadata, проверка всех DNS-ответов, подключение по проверенному IP, повторная проверка при каждом подключении | реализовано, проверено (unit) |
| Перебор паролей / 2FA | лимит неудач по email и IP (БД), одинаковый ответ для неизвестного email, argon2id, выравнивание тайминга | реализовано, проверено |
| Replay кода 2FA, fixation сессии | одноразовые шаги TOTP; ротация токена при повышении привилегий | реализовано, проверено |
| Кража БД | токены сессий хранятся как SHA-256; TOTP-секрет и SSH-ключ — AEAD (AES-256-GCM, привязка к контексту); master key вне БД | реализовано, проверено |
| Подделка аудита | триггер БД запрещает UPDATE/DELETE `audit_events`; секреты в `meta` не пишутся | реализовано, проверено |
| Произвольные команды на сервере | только 7 константных read-only команд (`ALLOWED_COMMANDS`), без подстановки ввода; вывод ≤64 КиБ и redaction | реализовано, проверено |
| Утечка ключей в ответах/логах | ответы и аудит проверены на отсутствие приватного ключа/паролей; ошибки валидации не эхо-ят ввод | реализовано, проверено |
| Prompt injection, LLM придумывает tool | модель не имеет прав: только read-only инструменты по сохранённым данным и `propose_plan` (ничего не исполняет); неизвестные инструменты и всё вне каталога/политики отклоняются и пишутся в аудит; контекст очищен, обрезан, помечен недоверенным; цикл ≤4 шагов | реализовано, проверено сценариями «послушной» модели (pytest); **реальные модели не проверялись** |
| Утечка секретов в промпт/ответ модели | redaction контекста и ответа; IP/порт/имя SSH-пользователя не передаются; ключ провайдера только в заголовке | реализовано, проверено |
| Мутация без approval / подмена плана | подтверждение привязано к (plan, revision, hash, actor, срок); хеш пересчитывается по содержимому; ревизия растёт при изменении; `approvals` append-only; роль owner/operator | подтверждение реализовано и проверено (pytest, e2e); **исполнения нет** — перепроверку в worker делать в Ф4 |
| Двойное списание | ledger + idempotency | не реализовано (Ф5) |
| Kill switch | `EXECUTION_ENABLED=false` | флаг в конфиге есть, мутаций нет (Ф4) |

## Известные ограничения
- `client_ip` — адрес прямого соединения; за reverse-proxy нужен доверенный `X-Forwarded-For` (Фаза 4). До этого лимит входа по IP нельзя считать надёжным за Caddy.
- Лимит SSH-операций — в памяти процесса (не разделяется между воркерами uvicorn).
- Не проведены: нагрузочные тесты, fuzzing, независимый security-review, проверка на реальном VPS и на Python 3.12.
- Сброс пароля/2FA и управление сессиями из UI отсутствуют.
- Worker на одном VPS с control plane — не полная изоляция (MD §3).
